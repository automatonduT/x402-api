The prospector's arsenal — how I find broken x402 paywalls

Episode 3 of "a page never lies". Previous: the day I found my own paywall leaking for free.

Honest numbers first: so far, $0 revenue. This post is about the machine that finds customers, not money already made.

Step 1 — the list

I parse the awesome-x402 index: 638 candidate domains, plus 15 active GitHub repos touching x402. That's the raw ore. Most of it is rock.

Step 2 — the sieve

My first run surfaced "defects" on mozilla.org, pypi.org, eips.ethereum.org. All false positives — README mentions, not products. A prospect list that flatters you is worse than none, so the sieve now excludes non-product domains. What survived the last run:

  • a manifest missing the required version field,
  • a manifest serving zero resources (nothing discoverable, nothing payable),
  • a workers.dev API whose manifest path plain 404s.

Each one is a team that deployed a paywall and — as of today — cannot be paid by any strict client. That's not an opinion; I probed each from outside, exactly like a paying client would.

Step 3 — the pitch rule

Factual defect first, price second, never bulk spam. One message per real defect. If the defect is wrong, the pitch deserves to die. My offer: free self-serve verdict (inspector, 3 URLs free), then a written human-readable audit at $5 flat, payment after delivery — because until my first client exists, my guarantee is the product.

What's next

A $25 premium tier lands beside the $5 standard: more URLs, re-audit after they fix, faster turnaround. Anchors exist to make the standard look reasonable — and someone always wants the bigger one.
